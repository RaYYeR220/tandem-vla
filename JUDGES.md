# Review this in five minutes

Prefer to watch first? The [4:43 demo video](https://youtu.be/A4MDmp8kii0) opens on a refusal and closes on the pour that misses.

Everything below runs from a clean clone with no API key, no GPU and no model download.

```bash
python -m venv .venv && .venv/Scripts/activate      # Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
```

## 1. The claim, in one command (≈2 seconds)

```bash
python scripts/eval_gate.py
```

This grades the safety gate — the piece the whole project rests on. It asks the gate to handle
an instruction naming an object that isn't in the scene, a pour with nobody holding the cup, a
pick with a full gripper, an arm sent to something it can't reach, and eight legitimate steps
that **must** be allowed through. That last group is the negative control: without it, a gate
that just returned `REFUSE` would score perfectly.

Look at the `reason` column. The gate explains itself in sentences, with distances measured off
the simulator.

## 2. Watch it work (≈3 minutes)

```bash
python scripts/evaluate.py --seeds 5 --out results/eval
```

Five randomized seeds of *"set the table for one and pour me some water"*. Per-seed subgoal flags
scroll past; a scorecard lands in `results/eval/scorecard.md` and every step of every episode in
`results/eval/episodes.json`, so any line of the summary can be traced to the episode that made
it. The run reports failures as prominently as successes — including the pour, which does not
work, and says why.

## 3. Speech to cutlery, in one command (≈3 minutes)

```bash
python scripts/voice_to_table.py --audio assets/audio/set_the_table.wav --seed 1
```

Partials stream in and settle into *"Set the table for one, please."*; a 1.5B model quantized to
INT4 parses that into an intent locally; the plan is expanded against the scene and gated step by
step; the arms run it. Each stage prints the backend that served it. With no API key it falls back
to a scripted transcript and a keyword parser, and says so rather than pretending.

## 4. The live dashboard (≈1 minute)

```bash
python scripts/serve.py          # then open http://localhost:8000/app.html
```

Pick a seed, press run. The plan tree fills in, each step stamped by the gate as it is checked,
with the inference HUD showing which model ran on which device at which precision. Ask for
something impossible and watch the refusal land.

## 5. The Intel story

```bash
python scripts/benchmark_intel.py
```

Prints the host, every OpenVINO device it can see with its real `FULL_DEVICE_NAME`, and
latency/throughput per precision per device. **Read the caveat it prints.** This was developed on
an AMD host with an NVIDIA discrete GPU; the script says so itself rather than letting a `GPU`
row be mistaken for an Intel iGPU. On a Core Ultra it enumerates CPU, GPU and NPU with no edits.

## Where to look in the code

| If you want to check… | Read |
| --- | --- |
| that the refusals are real and not prompt-engineered | `tandem/gate/__init__.py` — ~200 lines, no model anywhere in it |
| that the hand-off is structurally necessary | `tandem/sim/layout.py` — the staging region and the slots do not overlap either arm's envelope |
| that grasps are physical | `TandemEnv.jaw_contacts` in `tandem/sim/env.py` — read off `data.contact`; nothing is attached by fiat |
| that quantization is real | `tandem/bench/ovutil.py` — `ov.convert_model`, `nncf.quantize`, `ov.CompiledModel` |
| that the planner is honest about what ran | `tandem/planner/backends.py` — `info()` reports the backend that actually executed |
| what does not work | [`MOCKS.md`](MOCKS.md) — the hand-off relay and the pour, explained |
